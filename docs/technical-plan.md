# KeywordMap 기술 설계 메모

기획안(README) 기준의 초기 기술 설계 스케치. 구현 전 단계이므로 확정 사양이 아니라 **의사결정 후보와 근거**를 정리한 문서다.

## 1. 데이터 파이프라인

```
[수집] → [정제/지오코딩] → [키워드 추출] → [스코어링] → [줌 레벨별 집계] → [타일 캐시] → [API]
```

| 단계 | 하는 일 | 비고 |
| --- | --- | --- |
| 수집 (Collector) | SNS/포털/커뮤니티에서 지역 관련 게시물·검색어 수집 | 공식 API 우선. 크롤링은 각 서비스 약관·robots.txt 확인 필요 (아래 5절) |
| 정제/지오코딩 | 위치 문구·해시태그·좌표를 행정동 코드(법정동/행정동)로 정규화 | 통계청 행정구역 코드 + 국가공간정보포털 경계 데이터 |
| 키워드 추출 | 형태소 분석 후 명사/고유명사 추출, 불용어 제거 | Kiwi, Mecab-ko 등 한국어 형태소 분석기 |
| 스코어링 | 지역별 키워드 가중치 계산 | 2절 참고 |
| 집계 | 줌 레벨별(시도 / 시군구 / 읍면동) 상위 N개 키워드 산출 | 배치 주기 1시간 (핫이슈는 10분 단위 보조 배치 검토) |
| 캐시/서빙 | 줌 레벨 + 뷰포트(bbox) + 카테고리 조합으로 캐싱 | Redis, 혹은 사전 생성된 벡터타일 |

## 2. 스코어링

단순 언급량은 인구·상권 규모가 큰 지역에 편향되므로, **해당 지역 기준 상대적 급상승**을 함께 본다.

```
score(k, region) = tfidf(k, region) × burst(k, region) × recency(t)
```

- `tfidf`: 그 지역에서만 튀는 키워드에 가중 (전국 공통어 억제)
- `burst`: 직전 N시간 평균 대비 현재 언급량 비율 (신규 트렌드 포착)
- `recency`: 시간 감쇠 (예: 반감기 3시간)

동일 키워드가 인접 지역에 중복 노출되지 않도록, 상위 지역에서 채택된 키워드는 하위 줌 레벨에서 디듀프 처리.

## 3. 줌 레벨 ↔ 행정구역 매핑 (초안)

| 줌 레벨 (Mapbox 기준) | 표시 단위 | 화면당 노출 키워드 수 |
| --- | --- | --- |
| ~7 | 시/도 (17개) | 시도당 1~2개 |
| 8~10 | 시/군/구 | 구역당 1~3개 |
| 11~13 | 읍/면/동 | 구역당 3~5개 |
| 14~ | 상권/골목 (POI 클러스터) | 클러스터당 3~5개 |

- 라벨 충돌은 지도 라이브러리의 심볼 콜리전(collision detection)에 맡기되, 우선순위는 score 순으로 부여.
- 줌 레벨 14 이상의 '골목 단위'는 행정구역이 아니라 상권 폴리곤/POI 클러스터가 필요 → 초기 버전에서는 읍면동까지만 지원하고 이후 확장.

## 4. 아키텍처 후보

- **Frontend:** React + MapLibre GL JS (또는 Mapbox GL JS). 키워드는 GeoJSON `symbol` 레이어로 렌더링하고, 워드클라우드 느낌은 score 기반 `text-size` 보간으로 표현. 카카오/네이버 지도 API는 국내 지도 데이터가 강점이지만 커스텀 텍스트 오버레이의 자유도가 낮으므로 **MapLibre 우선 검토**.
- **Backend:** API 서버(읽기 전용, 캐시 우선) + 배치 워커 분리.
- **Storage:** 원천 데이터는 오브젝트 스토리지에 append, 집계 결과는 관계형 DB(PostgreSQL/PostGIS) 또는 키-값 캐시.
- **API 스케치**
  - `GET /api/keywords?bbox=...&zoom=11&category=cafe&limit=50`
  - 응답: `{ region_code, region_name, centroid: [lng, lat], keywords: [{ text, score, rank, category }] }`

## 5. 리스크 / 선결 과제

1. **데이터 수집 합법성:** X·인스타그램은 스크래핑이 약관상 제한적이다. 공식 API, 제휴 데이터, 공공 데이터(관광·상권), 검색 트렌드 API 등 확보 가능한 경로부터 확정해야 한다. **이 항목이 서비스 성립 여부를 좌우하는 최우선 과제.**
2. **지역 귀속 정확도:** 게시물의 위치 정보가 없거나 부정확한 경우가 다수 → 해시태그·본문 지명 매칭 규칙과 신뢰도 임계값 필요.
3. **콜드 스타트:** 데이터가 적은 지역은 빈 화면이 된다 → 최소 노출 기준 미달 시 상위 행정구역 키워드로 폴백.
4. **어뷰징/부적절 키워드:** 광고성·혐오 표현 필터링 파이프라인 필요.
5. **비용:** 지도 타일 호출량과 수집 API 쿼터가 주요 비용 요인.

## 6. MVP 범위 제안

- 지역: 서울 + 부산 (읍면동 단위까지)
- 카테고리: 맛집 / 카페 / 문화·행사 3종
- 갱신 주기: 1시간 배치
- 화면: 지도 1개 + 카테고리 토글 + 키워드 클릭 시 관련 게시물 링크 목록

MVP 목표는 "실시간성"이 아니라 **"지도 위 키워드가 재미있게 읽히는가"** 를 검증하는 것.
